NGI0 COMMONS FUND  /  GRANT 101135429  /  GPL-3.0-OR-LATER

Interoperable open tooling for fiber rollout

PRINCIPIA is a free and open-source toolchain for designing, documenting and validating fiber-optic access networks, FTTH, GPON and the underlying duct infrastructure, inside the open QGIS ecosystem. This grant funds the next major plugin releases.

01
SCOPE

What the grant funds

The grant supports the next major plugin releases, all on the same open codebase: a dedicated infrastructure data model and repeatable workflows that take a design through to documentation and QA without ever leaving open formats.

DELIVERED · v1.3.0Schema migrations for clean upgrades
DELIVERED · v1.4.0Automated topology and attribute validation with audit-ready reporting
DELIVERED · v1.5.0Import and export for round-trip compatibility (GeoPackage / GeoJSON), with a documented, openly licensed project-interchange format
DELIVERED · v1.6.0Performance on large projects through spatial indexing and batched operations, with a published before/after benchmark; and reliability: fewer crashes, and failures reported instead of silently swallowed
PLANNEDAutomated tests with CI

PRINCIPIA Designer, a separate browser-based companion developed independently as a commercial product, interoperates with the plugin through this open interchange format.

02
AUDIENCE

Who it is for

PRINCIPIA targets municipalities, smaller operators, contractors and engineering teams that today rely on proprietary CAD/GIS suites with non-portable data formats. The goal is an open data model these teams genuinely own: one that carries a fiber design from planning through to documentation and QA, and keeps it portable end to end.

NOVEMBER 2026  /  RELEASED  /  GPL-3.0-OR-LATER

v1.6.0 — WP4, performance and reliability

On a large design, the Optical Schematic View, the list of latent elements, the route correction check, Generate terminal slacks, placing a slack, PRINCIPIA’s own snapping in the placement tools, the undo record after every placement and Lay cable now use spatial indexes and batched reads instead of scanning every feature. The operations that save, export or import data now say when they fail, and why, instead of failing silently or reporting success.

FASTEROn a generated test city of 88,622 features in QGIS 3.44: the Optical Schematic View opens in 11.3 s instead of 16 min 39 s, and the list of latent elements in 5 s, where 1.5.0 did not finish in 30 minutes. Generate terminal slacks for 50 cables takes 0.4 s instead of 42.5 s, and nine mouse moves with the route tool 36 ms instead of 4.5 s
BENCHMARKPRINCIPIA 1.5.0, then 1.6.0, then 1.5.0 again, per QGIS version and city size: QGIS 3.44 (Qt5) and 4.0 (Qt6), test cities of 13,812 to 88,622 features (the largest on QGIS 3.44 only). Published with its method, every raw result file and its limits. By its rule, none of the 23 timed actions is measurably slower than in 1.5.0
LIMITSStated plainly in the report: on memory layers (a project not saved yet), every mouse move of the placement tools measured costs about 0.06–0.10 ms more than in 1.5.0. From 400 features the pole and element tools are still many times faster; the joint-closure tool stays slower at every size, by 0.18–0.20 ms a move at 20,000 features on QGIS 3.40. In a fresh QGIS, the joint-closure tool’s first nine moves are slower than 1.5.0’s in four of the five benchmark tables. The snaps still read every feature on PostGIS, WFS or GeoJSON layers, where the joint-closure tool is expected to be slower than in 1.5.0 (not measured). Section 9 of the report also lists the slowdowns measured during development
FAILURESSave all and Auto-save name the layers that did not save. Export layer, the BOM export, Import points, Import route, Merge routes, Change route type, Change element type, Delete selected, Undo and Redo, and Lay cable report a failed write with its reason. An unreadable relations, latent-elements or colour-catalogue entry is reported, and its text is kept in the project. A test stops silent error handlers from growing back. The hardening covers these operations, not every error handler in the plugin
CRASHESUnhandled Python errors fixed in route correction, the schematic view’s Center button, Import points and Import route, the BOM export to a locked or read-only file, and the slack tools on pre-1.0 projects. On QGIS 4, clicking an element with a picture now opens the picture
VERIFIEDThe full test suite on QGIS 3.22, 3.40, 3.44, 4.0 and 4.2, 2,275 to 2,308 tests each. Tested by hand on QGIS 3.40 and 4.2 with the release’s re-check list; its tests 19 to 31 were also replayed click by click in QGIS, 589 of 589 checks as expected. flake8, Bandit and the Qt6 check clean, the checks plugins.qgis.org runs
FUNDEDThe spatial indexing and batching behind the speed-ups, their benchmark, and the failure reporting and crash fixes listed above. Everything else in the release, including the fixes made during its release testing, was not funded by the grant

SEPTEMBER 2026  /  RELEASED  /  GPL-3.0-OR-LATER

v1.5.0 — WP3, an open interchange format

A fibre design is not a pile of points and lines: a slack loop belongs to a particular cable, a cable passes through particular manholes in order, cables are grouped into named routes. A generic export drops all of it, because those relationships live in identifiers local to one project file. Export interchange bundle carries them, keyed by an identity that survives the trip, and Import interchange bundle reads them back. The format is published, so the tool at the other end does not have to be PRINCIPIA.

CONTAINERGeoPackage (OGC 1.3) for a complete bundle, or a folder of GeoJSON files for web maps and quick handovers — explicitly marked lossy when relational data cannot come along
CARRIESCable references, pass-through elements and named cable groupings, all keyed by fiberq_uuid rather than by row numbers that mean nothing in another tool
PRESERVESAn element type PRINCIPIA has no layer for, an attribute it has no column for, and relational data it does not implement — fibre splices, trays, duct occupancy — survive a round trip unchanged. Nothing is ever reclassified to the nearest familiar type
SPECIFICATIONPublished under CC-BY-4.0 with a conformance checklist for readers and writers, plus the complete field and value mapping, generated from the code so it cannot drift
LEGACYPre-1.0 projects with the original Serbian layer and field names export the same bundle as a new one
VERIFIED378 tests on QGIS 3.44 (Qt5) and 4.0 (Qt6) in CI, including a round trip through a bundle deliberately richer than the plugin. Verified by hand on QGIS 3.40 and 4.2 across six scenarios; five defects were found that way and fixed, each with a regression test. Clean plugins.qgis.org security scan (100%)

AUGUST 2026  /  RELEASED  /  GPL-3.0-OR-LATER

v1.4.0 — WP2, validation and reporting

Validate project runs fourteen checks over the whole design and lists what it finds in a dockable panel. Filter by severity, layer or rule, click any issue to jump straight to it on the map, and export the run as a report. Verified end to end on QGIS 3.40 (Qt5) and QGIS 4.2 (Qt6), across four projects and two coordinate systems.

RULESTopology and connectivity, referential integrity, feature identity, required attributes, value domains, length coherence, CRS consistency, geometry health
REPORTSSelf-contained HTML for handover, JSON for tooling, CSV for spreadsheets and issue trackers
LENGTHSMeasured on the project ellipsoid — true ground metres, not map units. Recalculate lengths repairs existing projects, showing every change before writing anything
EXTRASA demo project with planted faults and the report it produces. Now translatable. Clean plugins.qgis.org security scan (100%)

IDENTITYfiberq_uuid, a stable cross-system ID on every feature
